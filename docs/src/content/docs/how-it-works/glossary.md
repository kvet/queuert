| Term                          | Definition                                                                                                                                                                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Attempt                       | One run of a job's handler. A job that throws is rescheduled and gets a new attempt. See [Job processing](/queuert/how-it-works/job-processing/#the-attempt-lifecycle).                                                                      |
| Backoff                       | The delay before a failed job's next attempt, growing with each consecutive failure up to a maximum. See [Retry and backoff](/queuert/how-it-works/worker-runner/#retry-and-backoff).                                                        |
| Blocker                       | A chain that another job waits for. The waiting job is `blocked` until every blocker chain completes. See [Job blockers](/queuert/guides/job-blockers/).                                                                                     |
| Chain                         | A sequence of jobs linked by `continueWith`, identified by its first job. It completes when its last job completes without continuing. See [Chain model](/queuert/how-it-works/chain-model/).                                                |
| Continuation                  | A job created by `continueWith` from the job before it. It shares that job's `chainId` and has its own `id`. See [Continuing a chain](/queuert/learn/continuing-a-chain/).                                                                   |
| Deduplication                 | A deduplication key passed to `createChain` makes a repeated call return the existing chain instead of creating another. See [Deduplication](/queuert/guides/deduplication/).                                                                |
| Head and tail                 | The head is a chain's first job, whose `id` is the chain's id. The tail is the job currently at its end. See [Chain model](/queuert/how-it-works/chain-model/#identity).                                                                     |
| Job                           | One unit of work with typed input and, once completed, output. Its status goes (`blocked` →) `pending` → `running` → `completed`. See [Chain model](/queuert/how-it-works/chain-model/#status).                                              |
| Job type                      | A named definition of a job's input and output, and of the types it may continue with. See [Job type references](/queuert/how-it-works/job-type-references/).                                                                                |
| Lease                         | The time a worker is live without a renewal; a running job is live while its worker's lease is. See [Worker lease](/queuert/how-it-works/worker-runner/#worker-lease).                                                                       |
| Notify adapter                | Delivers a notification when a job is created, so workers pick it up without waiting for the next poll. See [Notify adapters](/queuert/integrations/notify-adapters/).                                                                       |
| Processor                     | The handler for a job type, created with `createProcessors` and run by a worker runner. See [Job processing](/queuert/how-it-works/job-processing/).                                                                                         |
| Reschedule                    | Returning a job to `pending` for a later attempt, after a failure or through `applyJobOutcome({ reschedule })`. See [Scheduling](/queuert/guides/scheduling/).                                                                               |
| Slot                          | One unit of a worker runner's concurrency; it runs one attempt handler call at a time. See [Concurrency model](/queuert/how-it-works/worker-runner/#concurrency-model).                                                                      |
| State adapter                 | Stores jobs and runs status transitions in your database, through a state provider that wraps your database client. See [State adapters](/queuert/integrations/state-adapters/).                                                             |
| Transaction context (`txCtx`) | The object a state provider passes to your transaction callback. Spread it into Queuert calls such as `createChain` and `applyJobOutcome` to run them in that transaction. See [Transactional outbox](/queuert/learn/transactional-outbox/). |
| Worker runner                 | Created with `createWorkerRunner`. It polls for jobs, runs attempts in parallel slots and reclaims the jobs of workers whose lease expired. See [Worker runner](/queuert/how-it-works/worker-runner/).                                       |
