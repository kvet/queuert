The worker's lease, set by `leaseConfig`, is not a runtime limit: it bounds how long a crashed worker's jobs wait before another worker picks them up. Each worker's heartbeat renews its lease every `heartbeatMs`, however many attempts it runs, so a handler may run far longer than the lease's `durationMs`. The lease only expires when the worker stops renewing it — it crashed, its event loop stalled, or it lost its database connection. On SQLite, a user transaction that holds an async provider's write lock, or blocks the thread with a synchronous provider, past the worker's local deadline also makes the worker give up its lease. Either way the jobs running under it are reclaimed and start a new attempt. Use the cooperative `job.signal` pattern above for real runtime limits.

The worker runner below holds a lease of 1000 ms, renewed every 300 ms, and `rebuild-search-index` waits for its `job.input.durationMs`, which the example sets to 3000 ms: it completes on its first attempt because the heartbeat keeps renewing the lease. `heartbeatMs` must stay below a third of the lease's `durationMs`.
