Chains support various execution patterns via `continueWith`:

- [Linear](#linear) — `continueWith` returns the next type
- [Branched](#branched) — `continueWith` returns one of a union of types
- [Loop](#loops) — `continueWith` returns the same type until a terminal output
- [Go-to](#go-to) — `continueWith` jumps to a different type, skipping intermediates

A subscription lifecycle uses all four. Each job type lists the types it may continue with, and a type that declares `output` can end the chain:

## Continuation References

All examples above use **nominal references** — `{ typeName: "..." }`. Queuert also supports **structural references** (`{ input: {...} }`) that match any job type with a compatible input shape, enabling loose coupling. See [Job Type References](/queuert/how-it-works/job-type-references/) for details and examples.

See [examples/guides/src/chain-patterns.ts](https://github.com/kvet/queuert/blob/main/examples/guides/src/chain-patterns.ts) for the runnable code. See also [Job Blockers](../job-blockers/) for parallel dependencies and [Chain Model](/queuert/how-it-works/chain-model/) for how chains and their jobs are modelled.
