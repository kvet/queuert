A processor with a `batchAttemptHandler` receives up to `batchLimit` jobs of its type in one handler call, so it can do its side of the work in bulk — one API call, one query — and settle the jobs together or one by one. Processors with an `attemptHandler` receive one job per call.

:::caution[Experimental]
`batchAttemptHandler` and `batchLimit` are experimental: their API may change in a minor release.
:::

Settling a batch in one transaction pays the database round trip once per batch instead of once per job: on PostgreSQL, batches of 100 complete about an order of magnitude more jobs per second than single-job attempts (see [batched completion](/queuert/benchmarks/processing-capacity/#batched-completion)).

The `batchAttemptHandler` receives `jobs`, `applyJobOutcomes` and `fenceJobs`. Every job of the batch has its own attempt and its own `job.signal`, and settles once an `applyJobOutcomes` call that names it commits. Each item of `applyJobOutcomes` names a job of the batch as `job` next to one outcome: `output`, `continueWith`, `reschedule` (with an optional `reason`), or `fail`. It returns the committed jobs in the order of its items, each typed by its own item's outcome.

Jobs settled by one call share its transaction: if any of them was lost — reclaimed, completed elsewhere, for example by `client.applyJobOutcome`, or deleted — the call throws `JobsNotFoundError` for the deleted jobs if any, else `JobsAlreadyCompletedError` for the completed ones, else `JobsTakenByAnotherWorkerError` for the reclaimed ones, and aborts the `job.signal` of every lost job. Let the error roll back the transaction, so the call's writes for the jobs it still owns and the writes the handler made in that transaction roll back with it; the call's other jobs stay unsettled and can be settled by another call in a new transaction.

`{ fail: error }` fails one job: its `consecutiveFailures` goes up, `error` becomes its `lastAttemptError`, and it is rescheduled with the processor's backoff, while the other jobs named in the same call take their own outcomes in the same write.

## Per-job attempts

- `job.signal` aborts when that job's attempt is lost, and every job's signal aborts when the worker is stopping or lost its lease.
- Each job settles at most once. A call whose transaction rolls back does not count for its jobs, so they can be settled again.
- Jobs without a committed outcome when the handler ends, whether it returned or threw, fail: each counts a failed attempt and is rescheduled with backoff, with the handler's error as its `lastAttemptError`, or, when the handler returned, an error saying it returned without a committed `applyJobOutcomes` call for the job. Settled jobs keep their outcome.
- Await every transaction that calls `applyJobOutcomes` before the handler returns: a call still running when the handler ends races the failure of its jobs.
- To hand a job back for another attempt without a failure, settle it with `{ reschedule: { afterMs: 0 } }`.
- `fenceJobs({ ...txCtx, jobs })` locks and checks the named jobs, for writes the handler makes in a transaction that does not settle them; see [Job processing](/queuert/how-it-works/job-processing/#fencejob).

## How batches form

The worker runner never waits for a batch to fill. It takes up to `batchLimit` jobs of the type that are due when it looks, so a quiet queue runs small batches and a backlog runs full ones. All jobs of a batch have one type, and a batch takes one slot of the worker runner's `concurrency` until its handler returns: `concurrency: 4` with `batchLimit: 50` runs up to four handlers and 200 jobs at once. Each job of a batch still gets its own attempt log entries, which carry the slot as `workerSlot`, and its own `start job-attempt.{type}` span, which carries it as `queuert.worker.slot`.

`batchLimit` is required next to `batchAttemptHandler` and allowed nowhere else. It sets only the batch size: `batchLimit: 1` gives the handler batches of one job.

[Job attempt middleware](/queuert/guides/middleware/) wraps the whole handler call: `wrapHandler` receives every job in `jobs`.
