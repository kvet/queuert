`awaitChain` waits for a chain to complete by combining polling with notify adapter events. Between polls, it listens for completion notifications to react immediately.

<Diagram label="awaitChain polls the database and listens for a completion notification at the same time; it returns the output when the chain completes, or throws on timeout or abort">

Create the chain, then await it once the transaction has committed. `awaitChain` takes one options object: `chain` is the chain (or any `{ id, typeName? }`), `timeoutMs` is required, and `pollIntervalMs` sets how often the database is polled between notifications (default 15 seconds). `awaitChains` takes `chains` in place of `chain`, with the same options, reads the chains still running in one query per poll, and returns the completed chains in input order:

`signal` accepts an `AbortSignal`, such as the signal of the incoming request that is waiting for the result. Both a timeout and an abort throw `WaitChainTimeoutError`, or `WaitChainsTimeoutError` listing the chains still running from `awaitChains`, and the chains keep running.
