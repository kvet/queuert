## Deferred Start

Jobs can be scheduled to start at a future time using the `schedule` option. The job is created transactionally but won't be processed until the specified time.

<Tabs>
  <TabItem label="Relative delay (afterMs)">
    ```ts
    await withTransactionHooks(async (transactionHooks) =>
      client.createChain({
        transactionHooks,
        typeName: "send-reminder",
        input: { userId: "123" },
        schedule: { afterMs: 5 * 60 * 1000 }, // 5 minutes from now
      }),
    );
    ```
  </TabItem>
  <TabItem label="Specific time (at)">
    ```ts
    await withTransactionHooks(async (transactionHooks) =>
      client.createChain({
        transactionHooks,
        typeName: "send-reminder",
        input: { userId: "123" },
        schedule: { at: scheduledDate },
      }),
    );
    ```
  </TabItem>
</Tabs>

The same `schedule` option works with `continueWith` for deferred continuations:

```ts
return complete(async ({ finish }) =>
  finish({
    continueWith: {
      typeName: "follow-up",
      input: { userId: job.input.userId },
      schedule: { afterMs: 24 * 60 * 60 * 1000 }, // 24 hours later
    },
  }),
);
```

<Aside type="tip">
  Combine `schedule` with `deduplication: { key }` to prevent duplicate future jobs — for example,
  ensuring only one reminder is queued per user even if the trigger fires multiple times. See
  [Deduplication](../deduplication/).
</Aside>

## Rescheduling from a Handler

When a handler needs to defer work without treating it as a failure — for example, a rate-limited API saying "come back later" — use `finish({ reschedule })`:

```ts
attemptHandler: async ({ job, complete }) => {
  const response = await fetch(job.input.url);

  if (response.status === 429) {
    const retryAfter = parseInt(response.headers.get("Retry-After") || "60", 10);
    return complete(async ({ finish }) =>
      finish({ reschedule: { afterMs: retryAfter * 1000 } }),
    );
  }

  if (!response.ok) {
    throw new Error(`API error: ${response.status}`);
  }

  const data = await response.json();
  return complete(async ({ finish }) => finish({ output: { data } }));
},
```

Because `finish({ reschedule })` is a normal outcome — not an error — the job keeps a clean
slate: no `lastAttemptError`, no failure event, no error span. The attempt counter still
increments, so backoff reflects total attempts if the job later fails for real.

```ts
finish({ reschedule: { afterMs: 30_000 } }); // 30 seconds from now
finish({ reschedule: { at: new Date("2026-06-15T09:00:00Z") } }); // specific time
```

## Rescheduling Pending Jobs

A scheduled job is just a pending job with a future `scheduledAt`. Use `rescheduleJob` (or `rescheduleJobs` for a batch) to change when it runs. Omit `schedule` to run it immediately — useful for admin "run now" actions or manually advancing a queued reminder — or pass `schedule: { at }` / `{ afterMs }` to push it to a different time. Past times clamp to now, matching `createChain`.

```ts
// Run now
await withTransactionHooks(async (transactionHooks) =>
  client.rescheduleJob({
    transactionHooks,
    id: jobId,
  }),
);

// Push 30 minutes out
await withTransactionHooks(async (transactionHooks) =>
  client.rescheduleJob({
    transactionHooks,
    id: jobId,
    schedule: { afterMs: 30 * 60 * 1000 },
  }),
);
```

`rescheduleJob` throws `JobNotFoundError` if the job does not exist and `JobNotReschedulableError` if it is not `pending` (e.g. already running or completed).

`rescheduleJobs` validates atomically — if any id in the batch is missing or not pending, the entire call fails and no job is rescheduled. Both methods are mutating and require `transactionHooks` + a transaction context.

## Recurring Jobs

For periodic tasks like daily digests, health checks, or billing cycles, start a new independent chain from within the handler instead of using `continueWith`. This keeps each execution as its own short-lived chain rather than building an ever-growing chain history.

```ts
const jobTypes = defineJobTypes<{
  'daily-digest': {
    entry: true;
    input: { userId: string };
    output: { sentAt: string };
  };
}>();

// In processor — start a new chain with a scheduled delay
'daily-digest': {
  attemptHandler: async ({ job, complete }) => {
    await sendDigestEmail(job.input.userId);

    return complete(async ({ finish, transactionHooks }) => {
      const completedJob = await finish({ output: { sentAt: new Date().toISOString() } });

      if (userStillSubscribed) {
        await client.createChain({
          transactionHooks,
          typeName: 'daily-digest',
          input: { userId: job.input.userId },
          schedule: { afterMs: 24 * 60 * 60 * 1000 }, // Run again tomorrow
          deduplication: {
            key: `digest:${job.input.userId}`,
            scope: 'running',
          },
        });
      }
      return completedJob;
    });
  },
}
```
