Jobs can be completed without a worker using `completeChain`. This enables approval workflows, webhook-triggered completions, and patterns where jobs wait for external events. Deferred start pairs well with this — schedule a job to auto-reject after a timeout, but allow early completion based on user action.

## How It Works

The `completeChain` method calls your `handler` with the current job and a `completeJob` function. Pass the job to `completeJob`, then call `complete` with the outcome you want: `{ output: ... }` finishes the chain, `{ continueWith: {...} }` adds the next job.

Your handler can also decline: just return without calling `completeJob`. The chain stays untouched. Use this when the chain has already moved past the stage you meant to complete.

Over a [synchronous state adapter](/queuert/integrations/state-adapters/sqlite/#synchronous-providers), the `handler` and the `completeJob` callback must be synchronous: one that returns a promise throws.

Internally, `completeChain` locks the current job at the state adapter level, preventing concurrent completion by a worker or another caller. The Redis state adapter keeps workers off the job for at most 60 seconds and makes a second caller run its transaction again instead of waiting; see [Locks](/queuert/integrations/state-adapters/redis/#locks). The completed job has `completedBy: null` (no worker identity), distinguishing it from worker-completed jobs.

If a worker is already processing the job when `completeChain` runs, `completeChain` takes the job over. The handler's abort signal fires when the notify adapter delivers the attempt-lost notification, and its `complete`, when it runs, writes nothing and throws `JobAlreadyCompletedError`, so the handler's transaction rolls back. If the handler is inside a [fenced](/queuert/how-it-works/job-processing/#fence) transaction, `completeChain` waits for it to end, and if that transaction continued the chain, `completeChain`'s handler receives the continuation; on Redis, the one that commits second runs again instead.

See [examples/guides/src/workerless-completion.ts](https://github.com/kvet/queuert/blob/main/examples/guides/src/workerless-completion.ts) for the runnable code. See also [Tx Hooks](../tx-hooks/) and [Scheduling](../scheduling/).
