A job can continue the chain with a different next job depending on what it found.

<Diagram label="triage-ticket continues with either page-on-call or queue-for-support, and takes one">
  <Flow>
    <Node status="completed">triage-ticket</Node>
    <Rows spine>
      <Flow>
        <Arrow label="urgent" />
        <Node status="completed">page-on-call</Node>
      </Flow>
      <Flow>
        <Arrow label="otherwise" />
        <Node>queue-for-support</Node>
      </Flow>
    </Rows>
  </Flow>
</Diagram>

A job type lists every job type it may continue with, and a union is how it lists more than one: `continueWith: { typeName: "page-on-call" | "queue-for-support" }`. The types still describe all the possible paths, so a chain stays checked end to end.

The handler picks one at runtime. It reads its input, or anything it looked up in the same transaction, and passes the chosen job type and its input to `continueWith`. Only the chosen job is created, so a chain still runs one job at a time. TypeScript rejects a type that is not in the union, and checks the input against the type you chose.

The handler below sends every ticket to `queue-for-support`, so an urgent ticket never pages anyone.

<TryIt lesson="branching">make `triage-ticket` continue with `page-on-call` when `job.input.urgent` is true, and with `queue-for-support` otherwise.</TryIt>
