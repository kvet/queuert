A chain is Queuert's unit of work: your code creates it, a worker processes it, and you can wait for its result.

<Diagram label="The client creates a chain whose job is pending; a worker picks it up and the job completes; awaitChain returns its output">
  <Flow>
    <Node sub="client.createChain">your code</Node>
    <Arrow />
    <Node status="pending" sub="send-welcome-email">job</Node>
    <Arrow />
    <Node sub={<Transition from="pending" to="running" />}>worker</Node>
    <Arrow />
    <Node status="completed" sub="client.awaitChain">job</Node>
  </Flow>
</Diagram>

A job type names a kind of work and the shapes of its input and output. `defineJobTypes` declares them once, and both the client that starts chains and the worker that processes them read the same definitions, so a wrong input is a compile error. An `entry` type can start a chain.

Chains and jobs are rows in your own database. The lessons run on a real one inside your browser, PostgreSQL through PGlite or SQLite through sql.js; pick either above the editor. `db.ts` opens it, applies Queuert's migration and hands back the `stateAdapter` that the client and the worker read and write through. It also exports a small `sql` helper the later lessons use for their own tables.

`client.createChain` inserts the chain's first job as `pending`. A worker runner picks it up, runs the type's `attemptHandler` and completes the job through `applyJobOutcome` with its output. `client.awaitChain` waits for the chain and returns that output.

The code below already defines `send-welcome-email` and starts a worker runner that processes it. Nothing happens yet, because no chain asks for the work.
